AI Usage Log (10X CRM Project)
This document logs the strategic use of AI tools (Claude, Gemini, and ChatGPT) throughout the development of the 10X CRM application, highlighting goals, prompt refinements, evaluations, and technical takeaways in accordance with course standards.


Entry 1: Auth Guard Architecture & Route Security

Goal: Create a centralized access control mechanism in core.js to protect private routes (dashboard.html, clients.html, profile.html) and handle public redirects.

Tool & Prompting:

Tool: Claude (for code logic) & Gemini (for structural feedback)

Initial Prompt: "How to restrict access to html pages using javascript localstorage session?" (Result was unorganized and suggested duplicating code across pages).

Refined Prompt: "Write a single, reusable Vanilla JavaScript guard function inside core.js that checks for 'crm_session' in localStorage. If missing on protected pages, redirect to 'index.html'. If present on public pages (index, signup), redirect to 'dashboard.html'."

Outcome: Used / Adapted. Implemented guard(isPublicPage) in core.js. Gemini confirmed this approach satisfied the PRD requirement for a single entry point without duplicating files.

What I Learned: Structuring central utility functions prevents redundant code and keeps route logic clean across multi-page setups.



Entry 2: Form Validation & Registration Error Handling

Goal: Validate inputs on signup.html and index.html (Full Name length, lowercase email formatting, duplicate checks using .some(), and strong password rules).

Tool & Prompting:

Tool: ChatGPT (for prompt engineering) & Claude (for script generation)

Prompt: "Write a submit event listener for a sign-up form in Vanilla JS that collects all input errors into an object before displaying them. Validate full name (>= 3 chars), email syntax and uniqueness against 'crm_users' in localStorage, and password complexity (>= 8 chars, 1 letter, 1 number). Use preventDefault()."

Outcome: Used / Adapted. The generated snippet was adapted to match exact PRD error strings (e.g., "Full name must be at least 3 characters").

What I Learned: How to collect errors into an object to render all validation warnings simultaneously rather than stopping on the first failing field.



Entry 3: DummyJSON Data Fetching & Critical Bug Fixing

Goal: Fetch 30 default users from https://dummyjson.com/users?limit=30, map them into the CRM Client data model, and persist them in localStorage.

Tool & Prompting:

Tool: ChatGPT (code generation) & Gemini (debugging assistance)

Prompt: "Write an async function using fetch and try/catch to load 30 users from DummyJSON API, map them to Client objects (id, name, email, phone, company, status 'Lead', random dealValue), check response.ok, handle errors with retry logic, and save to localStorage."

Outcome: Critical Evaluation / Partially Rejected. The code generated by ChatGPT mapped company names as company: user.company, which rendered as [object Object] on client cards. Using Gemini for debugging, I identified that DummyJSON returns company info as a nested object (user.company.name). I manually corrected the property assignment.

What I Learned: AI code must be tested and inspected carefully. Never assume generated API mapping handles nested JSON objects correctly without verifying console output.



Entry 4: Client Filtering, Searching, and Non-Mutating Sorting

Goal: Implement getVisibleClients() in clients.js to process search inputs, active status filter chips (Lead, Won, etc.), and dropdown sorting without mutating crm_clients.

Tool & Prompting:

Tool: Claude

Prompt: "Write a Vanilla JS function getVisibleClients() that filters an array of clients by an active status chip string, filters by a search query on name or company using includes(), and sorts by Newest, Alphabetical, or Deal Value without mutating the original array."

Outcome: Used as-is. Chained .filter() and .sort() on a shallow copy of the state array.

What I Learned: Keeping state operations non-mutating avoids UI state bugs when toggling between search terms and category filters.



Entry 5: Dashboard Analytics & Timers (Clock and Reminders)

Goal: Display dynamic welcome messages, calculate pipeline metrics (active deals, won revenue via .reduce(), 7-day acquisition counts), and implement follow-up reminders.

Tool & Prompting:

Tool: ChatGPT & Claude

Prompt: "Write functions to calculate total clients, active deals, sum of dealValue for 'Won' clients using reduce(), and count of clients created in the last 7 days. Also write a live clock using setInterval and a 1-minute follow-up notification using setTimeout."

Outcome: Used / Adapted. Integrated the calculation logic into dashboard.js and added the setTimeout reminder feature inside the client details modal in clients.js.

What I Learned: Effective use of Array.prototype.reduce() for business analytics and proper handling of asynchronous JavaScript timers (setInterval and setTimeout).
